## Notes for the next worker

- `vm.runInNewContext(source)` without `filename` is invisible to Node coverage; use `new vm.Script(source, { filename: pathToFileURL(file).href })` (lessons L-0044, L-0053).
- `Object.defineProperty(root, name, { value })` in the UMD wrappers makes the page globals non-configurable. A script cannot be skipped and replaced later: leave it out of the
  composition and pre-define the replacement authority on the context instead.
- In a Node `vm` context `delete` of a non-configurable global returns `false` even in strict mode (a browser throws a `TypeError`); assert the `false` result and the surviving API.
- Objects built inside a `vm` context have the sandbox realm's prototypes: `assert.deepEqual` against host arrays fails, so spread the array or round-trip through JSON.
- A destructuring default (`{ crypto = webcrypto } = {}`) also replaces an explicit `undefined`; test for the key (`'crypto' in options`) when `undefined` is the scenario.
- The real catalog marks all 150 scenarios as available, so `unavailable-learning` is only reachable through a catalog the real validator accepts with one scenario switched to
  `{ status: 'unavailable', available: false, href: null, evidence: null }`.
