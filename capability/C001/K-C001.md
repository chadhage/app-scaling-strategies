## What the new tests prove

- Fail closed: whenever the guard rejects, throws, answers nothing or answers a decision that cannot be serialized, or `console.log` throws, the real `probe.cjs`
  exits 1, writes nothing that looks like a decision to standard output and writes exactly one line to standard error: allowed false, executed false and the single
  reason `PROBE_FAILURE` with the constant message. The underlying error text never reaches the visitor. A decision that the guard allowed (the control run exits 0)
  but that cannot be reported is never reported as allowed.
- Private ledger: the command line asks for `.docs\wiki\flow-state.json` under the repository root and nowhere else. With the approved record only `local.summary`
  and `local.probe` exit 0 (executed false, zero limits); each restricted or unknown action is denied with its own reason before the four fixed local-only reasons;
  drifted, missing, mis-keyed, array, text, invalid, blank and unreadable ledgers all deny with the ledger reason first and the guard reasons after it.
- Exactly one action argument: none, two or more is `INVALID_ARGUMENTS` first, never allowed. Requiring the module runs no command line.
- Exported function: the injected reader is called once with no arguments; a reader `SyntaxError` or bad text is `SOURCE_INVALID_JSON`, anything else `SOURCE_UNAVAILABLE`;
  the answer is frozen with the source reason first; an approval nested under `__proto__`, in an array, under another key or as a primitive is never authority;
  a non-string action (even an object that prints as `local.summary`) is `UNKNOWN_ACTION`.
- Sensitivity (`mutation-check.json`): 17 one-line mutants of a private copy of `probe.cjs` all fail the new files (unmutated baseline: 15 of 15 pass).

Authorities replaced in the child are collaborators of the module under test (the ledger bytes, and for the fault tests the guard's `guardOperation`); `probe.cjs` itself is always the
real file, and Node attributes the children's coverage to it because they inherit `NODE_V8_COVERAGE` (only `NODE_TEST_CONTEXT` is removed from the child).
The preload that serves the ledger is a tripwire, not a sandbox (L-0106): junctions, hard links and 8.3 names bypass it.

## Notes for the next worker

- The only uncalled function of `probe.cjs` is reachable only through a failing collaborator: the `--require` preload replaces `guardOperation` in `require.cache`, which makes the real script fail
  closed (lessons L-0031, L-0073, L-0074). Children keep `NODE_V8_COVERAGE`, so Node merges their coverage into the parent's report; only `NODE_TEST_CONTEXT` is removed.
- A node start costs 0.7 to 1.4 seconds at 100 % CPU: start the children of a test together (asynchronous `spawn`, `Promise.all`, hard timeout, `SIGKILL`). 36 serial spawns took 56 seconds;
  the same cases started together take about 7 seconds.
- With a guard that answers nothing, `probe.cjs` prints `undefined` to standard output before the `PROBE_FAILURE` line on standard error; the tests assert only that no decision reaches standard output.
- `capability\C016\tests\verify.cjs` hashes the whole of `capability\C001` before and after its run: do not edit or archive into `capability\C001` while it runs (an edit of this note during a first
  attempt forced a restart; that attempt was stopped before it archived anything).
- Consumer suites that wait on the State mutex or run real C015 workers (C045 guards and server tests, C019 `fixture.test.cjs`) fail or time out at 100 % CPU for reasons unrelated to K-C001:
  `green-04` and `green-05` are kept as failed attempts.
