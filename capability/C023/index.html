C023: checkpoint and effect ledger

Training fixture — synthetic data — not a live Azure result. H005 / P005 · one local S unit · fixture C023-r1.

Interrupt one versioned job, inspect its original attempt, and resume from its last checkpoint. The bundled profile and source stamps come unchanged from C020 getProfile; this page does not make a new HTTP observation.

What this model assumes

Atomic local pair: one synthetic effect application and its deduplication ledger entry are modeled together. A checkpoint is a separate later event. The controlled cuts are deterministic event-log cuts, not an actual process crash.

An unknown acknowledgment is unknown, not success. Retry is blocked until an explicit synthetic reconciliation observation resolves it. Those choices are not external receipts. There is no durable Storage, Queue, DB, external effect implementation, native proof, or exactly-once cloud guarantee.

Memory only: export before closing or reloading. Browser reload is not durable recovery. Archive/reset retains evidence in this open page, but creates a new isolated job, not a resume. Separate pages/files have no shared deduplication boundary.

Node.js 22 test tooling only; production Node.js 24 is unvalidated. No backend, framework, cloud calls, IaC, scaffold, registration, deployment or spending.
