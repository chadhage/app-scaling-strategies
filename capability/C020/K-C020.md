## What the new tests prove

- Refusals are exact: `UNEXPECTED_BODY` for Content-Length and chunked bodies (an empty declared body is fine), `URL_TOO_LONG` above 2048 characters (2048 still routes),
  `INVALID_URL` for a fragment, foreign authority, foreign absolute URL and a malformed target (two different messages), `INVALID_QUERY` on the scope record and every asset,
  `METHOD_NOT_ALLOWED` for HEAD, OPTIONS, POST, PUT, DELETE, PATCH and TRACE, and `LOCAL_HOST_REQUIRED` / `CROSS_ORIGIN_DENIED` for any host or origin that is not the exact listener.
  Every refusal has the exact JSON envelope and the full local header set; the guards run in the fixed order host, origin, method, body, URL length, URL shape.
- Exactly five assets are served, byte-exact with their content types; every other namespace entry and traversal form is `NOT_FOUND`.
  An unreadable asset is `FIXTURE_UNAVAILABLE` without the cause (a non-URL `TypeError` is not turned into a 400), other assets keep working, and the server recovers.
- `startLocal` creates no server unless a valid current approval is read (unreadable, malformed, missing, hollow, drifted or unresolved approvals are refused with their codes),
  binds only 127.0.0.1 on an ephemeral port, and rejects with the listen error.
- The CLI (real child process) prints exactly one record that equals the served scope record, drops an in-flight connection and stops listening on SIGINT and SIGTERM,
  exits 1 with the reason on stderr and no record when consent is unreadable, missing or drifted, and refuses any extra argument before it reads consent.
- Sensitivity (RED-02): 44 one-line mutants of a private copy of `server.cjs` all fail the new files only; the unmutated copy passes 26 of 26 (`mutation-check.json`, 44 killed, 0 survived).
  The only mutant class not claimed is the `remoteAddress !== '127.0.0.1'` operand of the host guard: a listener bound to 127.0.0.1 cannot receive another peer address.

Consent never comes from the live ledger: the tests build the ledger from the sealed approval in `capability\C001\approved-contract.js` and inject it (an `fs.readFileSync`
mock in process, the preload in the child). Windows cannot deliver SIGINT or SIGTERM handlers to a child, so the preload turns a stdin line into `process.emit(signal)`.
Every test and hook has an explicit timeout, every started server and socket is closed, every child is hard-stopped by its own handle, nothing is written to disk and nothing
but 127.0.0.1 port 0 is used. `K_C020_NAMESPACE_ROOT` is read only by the mutation check, which aims the unchanged tests at a private copy of the namespace.

## Notes for the next worker

- `vm.runInContext(source)` without `filename` is invisible to Node coverage (L-0044): the accepted consent-failure test never counted. Use the real module with a collaborator injected.
- A plain child `node server.cjs` keeps the inherited `NODE_V8_COVERAGE`, so its coverage is merged when it exits normally; only a nested `node --test` must drop it (L-0002).
- Raw `net` sockets with `Connection: close` send what `fetch` cannot: a GET with a body, a 2049-character target, `#fragment`, `//[` (`ERR_INVALID_URL`), absolute-form targets and HTTP/1.0 without Host.
- `--test-timeout` caps a whole test file in Node 22, not only a test; `headersTimeout` and `requestTimeout` are enforced only at Node's `connectionsCheckingInterval` (30 s), so a
  behavioral slow-client test would be slow. The 4 s drop window of the shutdown test stays below the 5 s `headersTimeout`, so a server that keeps in-flight connections cannot pass by timeout.
- `heavy-slot.ps1` and PowerShell: variables are case-insensitive, so a loop variable `$run` overwrites `$RUN`.
