# C017: reconcile cancellation during an in-flight action, and never fabricate an undo

**Synthetic, local, offline.** One fictional lease (`lease-synthetic-001`, run `synthetic-run-001`, user `user-synthetic-001`) runs ONE action, "stage synthetic capacity": 4 ordered steps of 5 synthetic integer units. A client may cancel it while it is in flight. The server owns the truth and answers every cancel with exactly one of five outcomes, each derived from an append-only journal and never from a claim. This is not the approved Node 24 + Express + Entra service, not a real service, and there is no Azure, cloud, real data or spend; those targets stay unvalidated and unregistered.

## The model in six rules

1. **The journal is the truth.** `journal.cjs` appends hash-chained, versioned lines (C015's canonical digest, flushed on every append). Each step writes an `step-intent` BEFORE it acts and a `step-effect` after. `reconcile.cjs` derives every status, fact and outcome from those entries alone, and `derive()` also checks the journal grammar: a forged decision (for example `COMPENSATED` without compensating entries) makes the whole journal unreadable, which is UNKNOWN, never "cancelled". The reader is a strict-grammar reader, not a canonical-form check and not a repair tool (see "What this does not claim").
2. **Cancel is cooperative.** A cancel received during step *k* waits for that step's boundary (an in-flight step is never reported as cancelled), then the action stops.
3. **Five outcomes, closed.** `CANCELLED_BEFORE_EFFECT` (200, no step had begun), `CANCELLED_PARTIAL` (200, steps 1..k STAND and remain, steps k+1.. were NOT run, nothing was undone), `CANCEL_TOO_LATE` (**409**, the action had completed, all effects stand, the cancel was not effective), `COMPENSATED` (200, only when journaled compensating steps ran in reverse order as their own entries with their own negative effects and 0 units stand; a failed compensation is `CANCELLED_PARTIAL` with `compensation: FAILED` and the failing step named), `CANCEL_UNKNOWN` (**503**, a crash or an unreadable journal; facts are `null` rather than empty lists).
4. **Idempotent and single-decision.** A command key is bound to one canonical command; the same key and command replays the journaled answer (also after a restart and a newer epoch), a different command under it is `IDEMPOTENCY_CONFLICT`. Only one cancel is decided per action (`CANCEL_IN_PROGRESS`, `ALREADY_TERMINAL`).
5. **Attribution.** Every command names lease, run, user, epoch and action; answers carry the server's own. Another lease, run, user or action, and a stale or future epoch, are typed failures (`UNKNOWN_*`, `STALE_EPOCH`, `FUTURE_EPOCH`) with allowed recovery actions (`reinspect`, `correct-closed-command`, `confirm-operator-review`, `stop`, `retry-identical`), `effectClaimed: false` and no journal write. The journal is bound to the same closed identity: `derive()` refuses an `action-accepted` entry that names another lease, run or user (a valid digest chain of a foreign run is UNKNOWN, never answered with the foreign identity).
6. **A restart tells the truth.** Opening a journal appends a `boot`. An action that was live at a crash is `INTERRUPTED` (never cancelled, never completed); an intent without an effect is an UNKNOWN step; a cancel that raced the crash replays as `CANCEL_UNKNOWN`. Reconciliation is an explicit `reconcile` command that settles the facts (`INTERRUPTED_KNOWN`, `INTERRUPTED_UNKNOWN`, `CANCEL_UNKNOWN`) and still never claims cancelled or completed.

## Run it locally

```powershell
node capability\C017\cli.cjs                      # steps paced 1500 ms, journal in capability\C017\state
node capability\C017\cli.cjs --step-delay-ms=300 --hold-in-step=3   # rehearse a crash: step 3 never finishes; kill the process, start again, open the page
```

The CLI rechecks C001 consent (the pattern of C020), binds **only `127.0.0.1` on an automatic port**, prints the exact URL and PID, and accepts no host, port, identity or outcome override (`--dir` must stay inside `capability\C017`). Stop with Ctrl+C, SIGTERM, the exact word `stop` on stdin, or the TTL (`--ttl-ms`, default 10 minutes). The page has Start, Cancel (with an optional compensation checkbox), Reconcile and Refresh: native buttons, so Tab, Enter and Space operate them.

## Browser observation and its limit

The shared isolated helper (`openIsolatedLoopback`) forwards only same-origin GET/HEAD and **blocks every write**, so the browser can never deliver a POST. `tests\browser.cjs` therefore (a) presses Tab and Enter on the page's own Cancel control and observes that a blocked request is reported as "not delivered … UNKNOWN: nothing is claimed as cancelled, stopped, started or undone", that the server journal holds no cancel, and that the retry would reuse the same key; (b) lets a Node client POST the cancel, compensation, too-late and reconcile commands and observes the page showing exactly the server's statement through GET (the DOM text equals the journal-proven statement); (c) observes a restarted interrupted action and a tampered journal. Six fresh Edge sessions run: in-flight, compensated, too late, interrupted, unreadable and FORGED. The forged session answers the page with a served GET only (the helper blocks POST): a loopback test double proxies the real server and lies about `/api/state` (it claims `COMPENSATED` while steps 1 and 2 STAND); real Edge must show the typed refusal "Answer rejected: the server's state view contradicts its own facts (...). No cancellation, undo or completion is claimed.", list nothing and leave every command button disabled. Forged POST answers (reconcile, typed failure, start, cancel) cannot be delivered through the helper: they are proved with the real `page.js` under the DOM stub (`page-forged-*.test.cjs`, `page-property.test.cjs`), a limit stated here and not hidden. After each session, the rendered element ids are unique and the journal numbering is the exact delivered sequence (L-0118). `evidence\browser-observation.json` (first publication, immutable) and `evidence\browser-observation-02.json` (final bytes, captured last with `$env:CAPTURE_BROWSER_EVIDENCE='browser-observation-02'`) record the DOM text, Edge's actual version, SHA-256 and Microsoft signature (the suite asserts signature and major 156, never an equality pin on the build). Closing an isolated Edge session is slow on a loaded machine (30 to 90 s per session observed, also against the first-publication code), so a full run can take several minutes. The key of an undelivered cancel is held in page memory so a retry reuses it; a reload loses it, which is safe because the server decides once per action and the reloaded page shows the journal-derived outcome.

## Resource and shutdown bounds (L-0111 to L-0113, L-0120)

One request per connection (`Connection: close`), 2 KB body, 8 KB headers, a 64-connection cap, 5 s request and 30 s idle timeouts, a state view capped at the last 48 journal entries, a 256 KB journal that refuses new actions (`JOURNAL_FULL`, 48 KB reserved so a live action can always be cancelled) instead of becoming unreadable, and every accepted socket tracked so shutdown cannot hang. **Close after every answer (L-0120, L-0132):** the ONE central `send()` closes the connection after the answer is flushed, after a bounded drain (at most 128 KB more request bytes or 1 s), for EVERY status the server produces (200, 403, 404, 405, 413, 415, 500). Node's own close at the end of a response waits for pending reads on Windows, which an endless `Transfer-Encoding: chunked` body of 1-byte chunks never lets finish: the first publication kept parsing such a body until the 5 s request timeout and a client in ANOTHER process starved the event loop for 2 to 5 s (the first-publication in-process test shared one event loop with its attacker and could not see it; its title and this sentence claimed the opposite). `chunked-process.test.cjs` now attacks every row of the shared refusal table (`refusals.cjs`: 12 request shapes) from a separate attacker process (`attacker.cjs`) against the real CLI in a small-heap child, and bounds the concurrent GET latency, the server-side event-loop delay sampled inside the child with `perf_hooks.monitorEventLoopDelay` and the time until the attacker sockets are closed, all at 3.2 s (the unfixed server keeps three attacker sockets open for 3.9 s up to the 5 s request timeout and starves the loop for 2 to 5 s; a machine saturated by three coverage suites and other builds was measured at up to 2.5 s without any flood, so the bound sits between the two, and a row gets up to three rounds because a loaded machine can stall the child by itself: the unfixed server breaks the bounds in every round on the 413 path); `chunked.test.cjs` proves closure in-process for the same table plus an injected 500 (it cannot see a stall and says so). A polite client that uploads a finite oversize body of up to about 128 KB still receives its typed answer; an endless, larger or slower one sees its connection reset (the 4xx may be lost). `resources.test.cjs` and `child.test.cjs` attack half-open, partial, never-reading, upgrade and CONNECT sockets, slow headers and bodies, oversize headers, pipelining and floods; `child.test.cjs` runs the real CLI in a child with `--max-old-space-size=48` under floods (heap growth bounded, still responsive, stops on `stop` with stuck sockets open) and kills it mid-action for the restart proof. The heap sample is published atomically (temp file plus rename) and read with a retry and a deadline (F1, L-0137).

## The page re-derives everything (F3, F8, L-0139)

`page.js` never prints server prose. Every `/api/state` view and every answer is checked by `contract.js` before anything is shown: `viewCheck` (identity, epoch, journal window with a closed list of entry types, steps, lists, standing units, status, cancel summary, reconciliation and the journal's own decisions must agree, and the cancel summary passes the same `claimCheck` as a cancel answer), `claimCheck` (cancel answers), `reconcileCheck` (closed determination, facts that partition the steps, determination consistent with the unknown steps), `startCheck` and `failureCheck` (the reason and allowed actions of a typed failure are the closed table's, never the answer's). Wording is re-derived from the facts (`statementOf`, `describeDetermination`) or taken from the closed table. An answer that fails is replaced by "Answer rejected: the server's <kind> contradicts its own facts (<fixed sentences>). No cancellation, undo or completion is claimed.", a refused view empties the page and disables every command, a rejected or unrecognized answer keeps the cancel key so a retry stays idempotent, and `showAnswer()` runs inside the same guard as the request (a malformed start answer no longer leaves the buttons disabled). The server's own 500 is now a typed failure of the closed table (`INTERNAL`). A reconcile statement after an interruption in the middle of a compensation names the journaled reversal instead of saying "nothing was undone" (found while fixing F4).

## What this does not claim

No power-loss durability (a regular file is flushed; the directory is not), no tamper-proofing (the chain and grammar detect inconsistency; a consistent rewrite of a whole valid journal is undetectable), no authentication or authorization (the fictional identity is a closed constant; the journal is bound to it, but nobody proves who the client is), no multi-process or multi-lease operation, no production Node 24 / Express / Entra validation. Journal rotation is an operator action. `--hold-before-step` and `--hold-in-step` are rehearsal flags for crash drills, not features of a service.

**Scope of the journal reader (F7).** `journal.cjs` enforces a strict line grammar and the digest chain; it does NOT enforce a canonical byte form and never repairs. A byte-order mark, CRLF endings, padded lines, reordered keys, a duplicated key (the last one wins) and `2.0` for `2` parse to the same logical record and are accepted while the record and its digest agree (`journal-forms.test.cjs` characterizes this); a changed value, a swapped or dropped line, an unknown field and a torn tail are unreadable, and nothing is repaired. The first-publication header comment claimed that any irregularity makes the journal unreadable; that was wrong and is corrected.

**Limits and mechanism limits, stated and not fixed** (reasons are the cost of a fix against what it would protect in a synthetic, loopback-only fixture; none of them lets the engine, the journal, an answer or the page claim a cancellation, undo or completion the journal does not prove):

| Limit | What happens | Why it is left |
| --- | --- | --- |
| F9: import pins | `imports.test.cjs` and `anchor.cjs` detect a changed pinned file, a changed transitive file and an extra static `require` of an unpinned namespace; a LAZY dynamic `require` of an unpinned namespace inside a function that never runs at load is not detected, and a bundle whose `imports.json` pins were re-signed is caught only by `anchor.cjs` against git, not by the in-namespace test | a static scan cannot see a computed require; closing it needs a runtime hook, which would be new production code for a case that needs a malicious committer |
| F10(a): journal capacity | any local client can fill the 256 KB journal in about 82 start, cancel and compensate cycles; every later start is a typed 503 `JOURNAL_FULL` until an operator rotates it (the view stays readable and the 48 KB reserve keeps the last live action cancellable) | the bound is the point (no unbounded growth); rotation is an operator action by design and there is no authentication to ration clients |
| F10(b): silent connections | 64 silent TCP connections lock a legitimate client out until the 5 s request timeout, and can be renewed | a connection cap is what protects memory; per-client fairness needs a client identity this loopback fixture does not have |
| F10(c): cancel on an interrupted action | a cancel with a NEW key on an INTERRUPTED action is answered 503 `CANCEL_UNKNOWN` without being journaled, so that key is not bound and may later be used for a different command; it never claims anything | journaling it would make an unsettled action carry a decision-less request that `derive()` must then treat as raced; the only way out is the explicit `reconcile` command, which is what the answer says |
| oversize bodies | a polite client uploading more than about 128 KB (or slowly) to a refused route sees a reset, not the typed 4xx | the price of cutting an endless body at once |
| browser | the helper blocks POST: forged POST answers are proved under the DOM stub, forged GET views in real Edge | the helper is shared and may not be edited |
