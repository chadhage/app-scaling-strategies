## The uncovered branches and how the tests reach them

Both files are UMD wrappers: under CommonJS they export, otherwise they register one global (`C004Provenance`, `C004Fixtures`), which is how
`index.html` loads them. The accepted suites only ever `require` them, so the browser branch was never run. `plan-fixtures.js` also returns a frozen
`{ unavailable: true }` when the C002 fixture or the C003 matrix is missing or unusable, a record the page reads to fail closed
(`!fixtures || fixtures.unavailable`); no accepted check reached that return either.

The new tests read each real source file and run it with `vm.Script` in a fresh context that has no `module`, `require` or `window`, under the real file URL so
Node attributes the coverage to the real file. Dependencies are injected the way the page's earlier script tags provide them: the real C002 fixture and the real
C003 matrix (and variants built from the real matrix). No part of the module under test is replaced or mocked. The checks:

- exactly one new global appears, it is read-only (assignment and redefinition throw), and the record is deeply frozen;
- its content equals the CommonJS export of the same file;
- local is resource-free with `not-applicable` pricing; native is unknown-resource with `missing` pricing, never zero;
- the native example follows the C003 `firstPlannedNativeTarget` flag, not row order or a remembered identifier;
- ten unusable states (never loaded, null, no rows, rows null, array-like, text, empty, no flagged row) give the frozen `unavailable` record with no local or native example.
