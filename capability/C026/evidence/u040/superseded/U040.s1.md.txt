# U040: nothing pipelined behind a refused request may upgrade, create a hub session or run (amendment of the accepted card C026)

Zero-credit defect fix (audit U038, lowest severity: no HTTP route mutates anything, the effect was a hub session) published under C026 / S. Everything here is **synthetic, local, offline** (loopback port 0, Node built-ins, no package, no Azure). The card is accepted and sealed: this item adds new files, changes four existing ones and supersedes their old bytes through `evidence-index-addendum-1.json`. `evidence.json` and every archive of the first publication and of the review fix stay byte-identical.

Observable behaviour changes (all follow from the rule "after a refusal nothing on that connection runs"): requests and upgrades behind a refusal get no answer and are never run; a refused request with `Expect: 100-continue` gets no `100 Continue`, and a read without content is answered without one; an unknown `Expect` header, a request without `Host` and unparsable bytes get the typed JSON refusal (417 `EXPECTATION_FAILED`, 421 `LOCAL_HOST_REQUIRED`, 400 `MALFORMED_REQUEST`, 408, 431) instead of Node's bare answer; `/transcript.json` answers `Connection: close`. Unchanged: a valid upgrade alone, a valid GET followed by a valid upgrade, keep-alive after an answered read, every refusal status and code.

## The amendment mechanism and what it cannot do

`evidence-index-addendum-1.json` (schema `C026-evidence-index-addendum/1`) is chained to the sealed `evidence.json` by its SHA-256 and lists, for a CLOSED list of four paths (`server.cjs`, `README.md`, `tests\evidence-final.test.cjs`, `tests\coverage-gate.cjs`), the SHA-256 of the replaced bytes, a byte-exact copy of them under `evidence\u040\superseded\` and the SHA-256 of the bytes that replace them; it also lists every manifest of `evidence\u040`. `tests\u040-chain.cjs` verifies the chain (a path outside the closed list, a changed sealed index, a tampered superseded copy, evidence or live file, a gap or a broken link are each rejected by name; `tests\u040-amendment.test.cjs` proves it with in-memory fixtures). `tests\evidence-final.test.cjs` and `tests\u040-evidence.test.cjs` pin that helper by raw SHA-256 (acyclic: a later helper edit needs addendum 2). `tests\u040-evidence.test.cjs` recomputes every archived run of this item (gzip hash, raw hash, byte count, input hashes), checks that the REDs ran against the superseded bytes and failed on assertions only, that the replay is the RED command and tests unchanged, the per-file coverage rows and the mutation report. A second change to any of the four files needs addendum 2 (`previous` = the hash of addendum 1, `previousRawSha256` = the bytes addendum 1 made live).

Limits, stated plainly: the namespace's own tests cannot detect a CONSISTENT rewrite of the verifier, the helper, its pin and the addendum together (the same limit as the C034, C016 and C021 amendment paths); the anchors outside the namespace are git history, commit `a52f05e2` (the bytes superseded) and the commit and tag of this item. The superseded copies and `README.md.txt` are evidence, not code (`.txt`). The archived runs of the first publication and of the fix keep hashing the old `server.cjs`; they are accepted only through the addendum. The browser observation covers the transcript page, not a browser WebSocket (inherited limit).
