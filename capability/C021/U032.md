# U032 - an owned, append-only amendment path for the C021 integrity test (files ADDED under C020)

Zero-credit unblock item, published under the original C021 / S card. It changes no page, no production file and no sealed evidence.
Training rehearsal, synthetic data, local only (no Azure, no network, no installs).

## Obstacle and change

`tests\integrity.test.cjs` test 1 ran `git diff --exit-code 2dc471da -- capability\C020` over the WHOLE accepted C020 tree, so any staged
or committed file ADDED under `capability\C020` (K-C020 adds tests, a spec and a note there) failed it. The sealed manifest `evidence.json`
pins the raw SHA-256 of that test (`4a399f82...`, test 6), so the test could not simply be edited.

U032 replaces exactly the bytes of `tests\integrity.test.cjs` through a chained, append-only addendum and keeps every modified, deleted,
renamed, type-changed or unmerged byte of the accepted C020 tree a failure:

| Path | Kind | Purpose |
| --- | --- | --- |
| `tests\integrity.test.cjs` | MODIFIED (the only one) | test 1 calls `amendments.c020Drift`, test 6 resolves the chain, a new last test pins the helper |
| `evidence-addendum-1.json` (and later numbers) | new | the chained addendum: supersedes `4a399f82...` by the new bytes, indexes the RED evidence |
| `tests\amendments.cjs` | new helper (tests tooling) | addendum chain, sealed and evidence checks, drift rule; pinned by raw SHA-256 in the integrity test |
| `tests\amendments.test.cjs` | new | specification: in-memory fixtures plus small scratch git repositories |
| `tests\amendment-replay.cjs`, `tests\tree-replay.cjs` | new | scratch replays (RED, controls, GREEN; whole-tree copy with files added under C020) |
| `U032.feature`, `U032.md` | new | specification and this note (the sealed `README.md` is untouched) |
| `evidence\u032-integrity-amendment\` | new | retained v1 test, retained stub, archived RED, controls and GREEN runs |

## How it works

* **The rule.** `amendments.c020Drift` runs `git --no-pager diff --exit-code --no-renames --name-status --diff-filter=MDTUXBR 2dc471da -- capability/C020`.
  The filter drops only Added (and Copied); with `--no-renames` a rename is a Delete plus an Add, so its old path is still reported.
  The test requires an empty list; a failure names every drifted path with its status. Git errors fail closed.
* **The chain.** `evidence-addendum-N.json` has a closed shape: schema, card, sequence, item, reason, `base` (path and raw SHA-256 of the sealed
  `evidence.json`), `previous` (name and raw SHA-256 of addendum N-1, null for 1), `amendments` and `evidence`. An amendment may name only the closed list
  `AMENDABLE` (`tests\integrity.test.cjs`), must name the exact bytes it supersedes (the sealed hash, or the previous head) and the exact bytes that
  replace them, and may not be a no-op or repeat a path. `evidence` entries index later files by raw SHA-256 inside
  `evidence\u032-integrity-amendment\` only, never a sealed file.
* **Acceptance.** `checkSealed` accepts a sealed source file only with its sealed bytes, except a superseded file: then ONLY the head bytes of the chain
  (the sealed v1 bytes are no longer accepted). A missing addendum therefore fails, because the live test no longer matches `4a399f82...`.
* **Acyclic pin.** The addendum holds the hash of the new integrity test; the integrity test holds the raw SHA-256 of `tests\amendments.cjs`
  (the helper holds no hash of the test). Editing the helper needs a new integrity test and a new addendum (see the end).
* **Sealed files stay sealed.** `evidence.json` and all other pinned bytes are untouched; the superseded v1 test is retained byte for byte in
  `evidence\u032-integrity-amendment\integrity.test.v1.cjs.txt` (raw SHA-256 `4a399f82...`).

## Protections of the old whole-tree form (kept and dropped)

Kept: modified, deleted, renamed (through its old path), type-changed and unmerged files of the accepted C020 tree, in the working tree, in
the index and in a commit; the byte-exact check of `contract.js`, `profiles.cjs` and `inspector.js` against the RED record (the only C020 files
the page and the tests load); the sealed hashes of every other C021 source.
Dropped ON PURPOSE: a staged or committed file ADDED under `capability\C020` is no longer reported, because K-C020 adds tests,
a spec and a note there; the content of an added file is not reviewed by C021. Never protected, before or after: untracked files (git diff
ignores them), ignored files, changes outside C020.

## What the mechanism cannot protect against

* A CONSISTENT rewrite of the integrity test and its addendum (and the helper pin) together passes every test inside the namespace (the test is
  the verifier). Only git history detects it: diff the verifier files against the accepted commit and recompute the pinned hashes.
* The tip of the chain is bound only by what it records. Addendum N is pinned by addendum N+1 (a changed byte breaks the link), but deleting
  the newest evidence-only addendum only drops its evidence index. Prose fields (`reason`, `edit`) of the newest addendum are not checked.
* The helper pin and the head hash protect bytes, not intent: the replaced test is trusted as written.

## Amending again (addendum N+1)

Never rewrite a published addendum, the seal or `evidence.json`. Write the next `evidence-addendum-N.json` with `previous` = name and raw SHA-256 of
addendum N, the same `base`, and for a changed integrity test one `amendments` entry (`previousRawSha256` = the current head, `rawSha256` = the new
bytes). A changed helper needs a changed integrity test (it pins the helper) and therefore such an entry; evidence-only addenda leave `amendments` empty.
