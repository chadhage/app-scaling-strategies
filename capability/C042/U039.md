# U039: close every refusal and never run a request pipelined behind it (addendum to the sealed C042 README)

`README.md` of this card is the accepted text, amended in ONE place (the "Responses" bullet of "Resource bounds"). This file is the addendum: what was wrong, what changed, how the sealed bytes were superseded, the exact commands and the limits. Specification: `U039.feature`. Zero-credit defect fix found by the U038 audit; nothing outside this namespace changed (C043 and C059 import `contract.js`, `input.cjs`, `engine.cjs`, `journal.cjs` and `result.cjs` only, none of which changed; they never import `server.cjs`).

## The defect

Node parses every pipelined request of one TCP read and emits each `request` event before the first answer has finished. The accepted `server.cjs` decided about closing only on the `finish` event of a refusal and only for a body it had not read, so (a) after a bodiless or read-body refusal (404, 405, 421, 403, 400 invalid JSON, ...) the connection stayed open and `[refusal][POST /v1/steps]` APPLIED, with both answers delivered, and (b) behind a 415 (unread body, `Connection: close`) the mutation APPLIED while the client received only the 415. The U038 audit measured 27 of 28 refusal variants applied, 2 of them hidden. The same holds for the answers Node gives itself (an unknown `Expect`, a request without `Host`, a parse error, `CONNECT`) and for HTTP/1.0 framing. The archived RED of this item (`red-07-final-tests`) measures the larger matrix below against the accepted bytes.

A THIRD HOLE was found after the first fix (the review of C059, finding N1, and the controller note of 6 Nov 10:04; orders\_PIPELINING.md): a refusal that Node decides at PARSE time ran outside the per-connection lane and, when it marked the connection `closing` at once (a parse error, `CONNECT`), it dropped the legitimate requests pipelined BEFORE it: `[G][G][garbage]` got `[200, 400]` instead of `[200, 200, 400]` (48 of the 130 lane rows on the first fix, `red-06-lane-first-fix`). The unknown-`Expect` rows, the rows without `Host` and a burst of 128 sockets already behaved correctly. The second fix below closes it.

## What changed in `server.cjs`

- ONE rule: EVERY refusal (status 300 or above, or a request whose body was not read) is answered with `Connection: close`; the connection is added to a `WeakSet` synchronously inside `send`, at decision time, using `request.socket` (never `response.socket`, which is null while a response waits behind an unfinished one), and the socket is destroyed once the answer is flushed.
- An ordered per-connection queue: a pipelined request starts only after the answer before it has been sent (the lane is released on the `close` of its response; no listener is added per request). After an `await`, a refusal therefore also drops what was queued behind it. At the top of the handler a request of a marked connection is dropped without reading its body and releases the request queued behind it; a connection that is gone is marked by ONE `close` listener per socket (a client that left is not served), so the mark is the single source of truth. The depth bound of 4 is unchanged.
- Node-own answers go through the same rule: `checkExpectation` (unknown `Expect`: typed 417), `checkContinue` (`100 Continue` is written only for a request that will be read), `clientError` (parse error 400, oversized header 431, timeout 408) and `connect` (405), `requireHostHeader: false` (a request without `Host` reaches the handler and is refused 421 like a foreign Host). An unparsed request has no response object: the connection is paused (read no further), a SECOND `WeakSet` (`unparsed`) makes sure the typed refusal is written once, and it is written after the lane of the requests before it has settled, so those requests are answered IN ORDER first; only then the socket ends and is destroyed after the flush. The connection is deliberately NOT marked `closing` by a parse-time refusal: that mark drops the requests queued before it (the third hole).
- Decisions (the closed contract is pinned by C043 and C059, so no code was added): the typed body of the Node-own answers is `INVALID_FORMAT` with a `details` path (`expect` or `request`) and keeps the status Node would have chosen (417, 431, 408, 400); `CONNECT` is `METHOD_NOT_ALLOWED`; a parse error and `CONNECT` answer the requests pipelined BEFORE them first (the first fix dropped them: reversed by the third hole above, and the test that encoded the old decision is inverted).

No existing C042 test asserted a kept-alive connection after a refusal, so no sealed test was inverted (C059's `tests\server.test.cjs:134` does and is out of scope here).

## Honest limits

- Loopback only, Node 22 here (the production target is Node 24: `requireHostHeader` exists in both). HTTP/1.1 and HTTP/1.0 framing (also `Connection: keep-alive` negotiation) are probed on every row; an h2c upgrade header is probed (ignored by Node: an ordinary request); HTTP/2 prior knowledge, TLS and a front proxy are NOT probed. `Expect` is applied by Node only to HTTP/1.1, so that row runs with a 1.1 refused request only.
- The matrix drives one mutation (`POST /v1/steps`, and `POST .../cancel` for the step-bound row); the other mutating routes (`cancel`, `resume`) pass through the same handler and refusal function.
- A refusal whose unread endless body is still arriving can lose its answer to the reset that follows the close (Windows); the flood test therefore requires closure and no served follow-up, not the answer, for that kind.
- The two-writes variants tolerate a reset before the answer is read (the state and the closed connection are still required).

- COVERAGE MEASUREMENT of `server.cjs` (resolved in this slice): Node re-injects `NODE_V8_COVERAGE` into every child process whose environment object has no OWN key of that name, so deleting it does not help (L-0140). - Time: no test verdict depends on a duration shorter than ten minutes except two liveness bounds: the child watchdog, test timeouts and nested-run timeouts are orphan guards of 15 to 30 minutes, and `U039_CLOSE_MS` (20 s; 1500 ms for the RED runs, 2000 ms in the mutation tools) bounds how long a connection that must be closed by the server may stay open: a correct server could in theory exceed it on a stalled machine, which turns a pass into a failure, never a failure into a pass. The timer for silent connections is tested on a MOCKED clock (a real 150 ms timer racing the first write failed two whole-suite runs on a saturated machine: the two retained `coverage-05-final-*` captures).
