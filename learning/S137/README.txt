WHAT THE SEVEN CHECKS MEAN
Same old bundle, new backend version, old worker/cache/bundle lineage, two
required old asset content IDs, catalog-v1 API shape/types, ui-draft-v1 state
and correct rendered-result DATA are checked separately. Additive server
metadata is compatible; renamed fields or a string stock value are not.
Asset paths and content IDs are fictional records, not requested files or
cryptographically measured deployment content. No service-worker bundle runs.

Preserved: 7 PASS, POSITIVE.
API shape, missing asset, changed asset, lost state or corrupt render:
6 PASS / 1 FAIL, NEGATIVE, even with a fresh backend and warm-up HTTP 200 DATA.
Backend-only: 2 PASS / 5 UNKNOWN, UNKNOWN.
Cache-unknown: 6 PASS / 1 UNKNOWN, UNKNOWN.
Only POSITIVE permits the candidate sample view within the fixed fixture.
NEGATIVE and UNKNOWN withhold it and retain the safe Paper star x 2 view.
Recorded attempted corruption is shown as DATA, never silently installed
as the sample view. A new backend or HTTP 200 alone cannot certify an old
client bundle's compatibility.

BOUNDS / GUARDS
Maximum 12 measured runs and 64 accepted actions, including resets. Pin reserves
room for cutover, measurement and reset. Accepted results/events are not trimmed;
new work is rejected at the envelope. The latest 12 rejected actions are shown;
older errors are intentionally outside this finite error window.
The model accepts exact plain data actions, exact typed preset IDs and canonical
state only. Extra keys, symbols, accessors, coercion, bad numeric types, forged
nested verdicts/bundle IDs/counts and impossible event order are rejected.
Bounded replay reconstructs all accepted history from fixed immutable DATA
before any new action, rather than trusting cached results.
