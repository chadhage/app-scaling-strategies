S066 · Did the transaction commit?

A-S066 · D-S066 · SC-S066 · one frozen S learning unit

Fail during commit, reconcile authoritative receipts, and avoid applying the same operation twice.

Three operations, one effect each

Each fixed operation SYN-661, SYN-662 and SYN-663 intends exactly one synthetic effect. Failover loses all three commit acknowledgements. A timeout is neither a commit receipt nor an abort receipt.

Reconciliation supplies a durable commit receipt for SYN-661 and a terminal abort for SYN-662. Choose later evidence for SYN-663. Missing evidence is never proof of abort.

  1. Choose the uncertain receipt and recovery policy. Begin commits, then inject failover.
  2. Reconcile original outcomes before applying recovery. Inspect both original and recovered attribution.
  3. Compare effect bounds and duplicates. Predict the gate; a correct learning answer does not repair failed users.
  4. Try another bounded attempt with retained history, or explicitly reset all local memory.

Fixture assumptions: authoritative receipts cover the original commit attempt. A terminal abort cannot later commit. A confirmed-abort retry with the original operation key and unchanged payload produces one effect and its receipt in a synthetic durable deduplication ledger. This ledger is an assumption, not an implementation or proof of a database guarantee.

What this does not prove

      
This bounded, deterministic portable model runs entirely in browser memory. Three operations per attempt,
        nine combinations, at most six retained attempts, no clock, real database, transaction, replication,
        durable storage, concurrency, actual commit or failover. No real authentication, registration, credentials,
        cloud calls, management access, IaC, deployment or spending.

      
Receipt authority and retry completion are supplied fixtures, not measured native behavior.
        UNKNOWN is not success. A correct prediction is only a learning-verifier result.
