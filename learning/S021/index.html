Objective

Admit the declared required pool only when every required candidate has fresh, identity-bound ready evidence. A healthy aggregate endpoint reply is not evidence about the other instances.

Optional instances stay outside this required routing pool. Optional dependency failures remain visible without becoming blanket safety gates.

Preconditions for this model

  • Required: candidate-a, candidate-b, candidate-c; optional: candidate-shadow.
  • Deployment: candidate-v2. Fixed clock: 120000 ms.
  • Freshness: age ≤ 30000 ms, including the boundary.
  • primary-store is required; recommendations is optional. Dependency observations belong to the same per-instance snapshot.
  • Every required identity must be explicit and unique. Missing entries in the required pool or dependency contract block admission rather than silently becoming optional.
  • Isolated local fixtures only. No subscription, server, credentials, or installation needed.

Worked exercise

Change the evidence. Challenge the gate.

  1. Choose a concrete preset and inspect each required candidate.
  2. Change one instance or the aggregate sample. Predict ALLOW or BLOCK.
  3. Inspect the verification verdict and trace; keep actual user impact separate.

Presets supply their expected verdict. Custom changes preserve your prediction so an incorrect prediction can fail without bypassing admission.
