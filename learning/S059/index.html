Interpret one shared setting with old and new code. Detect a meaning change even when both versions appear healthy.

Worked contract

Both deployed versions read the same synthetic retryBudget value. Under the approved retries-v1 schema, it means extra retries after the first attempt. Thus a raw value of 2 permits 3 total attempts.

The synthetic dependency fails attempts 1 and 2, then succeeds on attempt 3. Compatible new code preserves the legacy meaning. Divergent new code treats that same value as total attempts. Changing the schema to attempts-v2 does not upgrade the old reader.

  1. Inspect the default draft: both readers allow 3 attempts and both journeys succeed. Publish that checked draft.
  2. Choose divergent new code and inspect value 2: old code succeeds, new code fails. Try publishing; the prior publication must stay unchanged.
  3. Try divergent value 3: both journeys succeed, but 4 versus 3 allowed attempts still blocks publication.
  4. Try a missing observation or attempts-v2; uncertainty and unsupported readers never pass. Restore compatible retries-v1 value 2 and inspect again.

Publication requires an exact-draft check, matching approved meanings and two successful journeys. Each inspection is two fresh synthetic probes, not a distributed rollout. Preparing compatible code precedes flag activation (source S010); no real deployment occurs here.

Operator controls

Integers 0–4 for retries-v1; 1–4 for attempts-v2. No expressions, decimals or credentials.

Limits and evidence

This finite in-memory model has two readers, one setting, at most five allowed attempts per probe, and 16 retained measured actions. It models no propagation timing, real retries, network, authentication, deployment or configuration store. Missing observations stay unknown. A successful negative test is not a successful user transition.

This is not native Azure evidence, real distributed-configuration proof, Node.js 24 production validation, five-nines certification or completion of B-S059, D-S059 or prerequisite D-S010. Actual browser checks qualify only the recorded local Node.js 22 / Playwright 1.56.1 / signed Edge 156 tooling pair.
