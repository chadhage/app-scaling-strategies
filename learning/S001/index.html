Warm v2, then hand off

Practice readiness-gated admission without abandoning work already running on v1.

This portable lesson is not B-S001 native proof and does not complete D-S001.

Objective and preconditions

Prepare v2 beside v1, verify representative journeys, then move only eligible new admissions. A healthy endpoint or a desired routing change alone cannot establish a successful migration.

  • Independent, controlled v1/v2 routing is assumed; this is not a native slot swap.
  • Two ready candidate instances, compatible configuration and dependencies, and two overlap capacity units are required.
  • An isolated signed-in fixture carries cart quantity 3; each journey must produce exactly one business effect.
  • Each complete journey has an inclusive 500 ms budget. Readiness evidence must be for v2@1 and no older than 1000 ms.
  • old-001 starts on v1, still running with its effect pending. New admissions are not a transfer of that old work.
  • Retirement needs observed old-work completion and a separate 1000 ms simulated rollback retention window after handoff.

Work the handoff

Safe path: warm-up → hand off → finish old work → advance retention → retire v1.

Unsafe challenge: reset, then hand off before warm-up. Expect FAIL, even though the guard keeps users on v1. A failure or unknown needs a reset before a new scored exercise.

Synthetic conditions

Changing conditions resets only this page's local exercise. All inputs, effects, and durations are invented, deterministic snapshots; no time is actually awaited.

    Boundaries, evidence limits, and IaC
    
      
      
        
    • PASS means only that this tiny invented fixture matched its assertions. It is not a live Azure result, reliability certification, uptime measurement, or five-nines proof.
      • 
        
    • FAIL can describe a safely blocked operator choice or an interrupted exposed journey. User impact is reported separately so a safe abort never looks like a completed migration.
      • 
        
    • UNKNOWN covers missing or stale evidence. A missing destination stamp is not replaced by intended routing; an empty sample never becomes 100% success.
      • 
        
    • Latency 500 ms passes; 501 ms fails. Evidence age 1000 ms passes; 1001 ms is unknown. A missing effect observation is unknown; zero or two effects fail.
      • 
        
    • This model assumes controlled admission and compatible retained v1. Native slot recycling, real authentication, capacity, durable state, data ownership, provider behavior, and rollback feasibility need separate B-S001 evidence.
      • 
        
    • IaC: N/A. SOURCE read-only synthetic lessons need no Azure resource. C001 runtime/auth/hosting and separate scaffold/deploy approval remain absent.
      • 
        
    • No credentials, cookies, persistence, framework, telemetry, network calls, management operations, or external assets. Reload or reset clears local memory; no cloud cleanup is performed.
      • 
      
    
      
    Local evidence: BDD cases, Node tests, execution evidence, and lesson manifest.
