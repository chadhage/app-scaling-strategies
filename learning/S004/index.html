Hold 50/50. Observe. Then converge.

A healthy A/B experiment preserves stable cohorts and equivalent state/effects. It does not mean every user migrated. Requesting 100% is not observing 100%.

A worked local experiment

  1. Hold three healthy rounds. Expect ten observed users on each version, schema 1, three tickets each, and exactly one effect per retried transaction.
  2. Hold again. Stable cohorts remain split. More time does not complete migration.
  3. Request convergence to v2. Desired routing changes; the previous observations do not.
  4. Observe convergence. Only a new compatible sample can show all twenty fixture users on v2.
  5. Reset and break it. Try unstable assignment, incompatible v2 state, or missing evidence. A passing negative guard check is not a passing user outcome.

Preconditions, not measured readiness: two invented available versions, sufficient capacity, a shared account contract and synthetic identities. No availability, identity or cloud capability is verified here. One round is one simulated minute; no real soak runs.

1. Choose a condition and act

Each round retries one ticket operation per user. Both versions should spend one credit, issue one ticket and share the same deduplication key. The local rehearsal is bounded to 100 total rounds.

Convergence requests are deliberately clickable during a bad or unobserved split so you can inspect the refusal. Later passing probes cannot erase failed/unknown history. Reset clears only local memory and begins a separate practice attempt.
