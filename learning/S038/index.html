S038 — Tenant authorization continuity

Preserve permissions and isolation after routing changes. A-S038 · D-S038 · SC-S038 · one S unit.

A route change must not change who may read whose data

Alba and Birch each have one synthetic member and one synthetic record. Members may read their own tenant's record; foreign reads must return 403 with no data. A forbidden 403 is a successful isolation assertion, not an interrupted authorized read.

Before the change both tenants route to v1 and both directly reachable versions are isolated. Choose each after-change destination and v2's after-change policy. v1 stays isolated. Probe both reachable versions before and after, including an endpoint not selected by the routing controls.

The fixed matrix is 2 phases × 2 versions × 2 members × 2 read intents = 16 probes per run. Both versions remain reachable; this exercise does not retire them.

    Worked exercise

    1. Run the defaults: SUCCESS; 16 success / 0 failure / 0 unknown. Both tenants have observed authorized v2 route reads.
    2. Choose allow foreign-tenant reads: FAILURE; 14 / 2 / 0. Inspect the two v2-after foreign reads returning 200 and another tenant's record.
    3. Uncheck Foreign-read rejection and run again: UNKNOWN; 8 / 0 / 8. The leak is still visible, but an omitted assertion cannot certify isolation. Re-enable it.
    4. Choose own read returns foreign data: a 200 response is not enough; the data-tenant assertion exposes two failures. Denying own reads also fails continuity.
    5. Choose v2 responses unobserved: UNKNOWN; 12 / 0 / 4. No response status or data is invented.
    6. Reset, leave Alba on v1 and move Birch to v2, then inject foreign access. Even Alba's directly reachable v2 endpoint must reject foreign reads. A healthy selected route is not universal proof.

    Scope and limits

    This is a bounded deterministic policy fixture, not real authentication, token validation, a security test against a service, or native Azure evidence. The members, records, responses, routing and policy faults are synthetic. No credentials, registration, network calls, timers, storage or cloud resources are used.

    Verifier PASS means only that this selected synthetic matrix was complete and passed. FAILURE records permission loss or isolation failure; UNKNOWN means missing observations or assertions. Healthy direct probes do not prove both tenants migrated. Real users are UNMEASURED; no cleanup resources exist. B-S038 and the source-demo gates remain unverified. No production Node.js 24 or five-nines claim is made.
