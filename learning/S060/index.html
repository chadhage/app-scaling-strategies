The contract that decides recovery

Two synthetic orders start at USD 3500 minor units. v1 requires totalCents and assumes USD. Evolving commits a third order before recovery, so discarding new writes cannot count as success.

  • Compatible: additive notes retain totalCents; the new USD 500 order remains readable by v1. Roll back the application, not the schema. Expected: 3 orders, USD 4000.
  • Irreversible for v1: remove totalCents, store currency-aware minor units and commit EUR 700. v1 cannot interpret that contract. Expected: 3 orders, USD 3500 and EUR 700. Explicit v2.1 forward recovery is required.

No down migration, backup restore, conversion to USD or actual database transaction is modeled. “Irreversible” is relative to the declared v1 contract, not a claim that every real migration is unrecoverable.

Measured synthetic result

The event boundary is the recovery action and its fixed three-order read journey. All attempted recoveries, including failures and unknowns, remain in the denominator. A rejected unsafe reversal is a separate safe abort. The synthetic budget is 10 ms; an available fixed read takes 7 ms. Neither number measures a real system.
