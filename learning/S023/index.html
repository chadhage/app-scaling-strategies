Representative journey warm-up

A healthy endpoint can hide a broken transaction. Require isolated login, an owned-profile read, and a verified transaction receipt before calling the candidate ready.

Conduct the comparison

  1. Run the default shallow probe. Its HTTP 200 leaves business readiness unknown.
  2. Select the representative path with the same rejected-transaction fixture. The transaction now fails.
  3. Choose the healthy fixture. All three business assertions must pass within the journey budget.
  4. Try a missing receipt, a 99 ms budget, or the isolation guard. Keep failures and unknowns in view.

Preconditions: a local browser only. All identities, profiles, receipts and ledger markers are fixed, in-memory training fixtures. No credentials, real accounts, network, payment, email or database operations.

Operator controls

Deterministic fixture timing: endpoint 10 ms separately; login 15 + read 25 + transaction 60 = 100 ms. Unobserved or skipped steps have unknown journey latency, never zero.
