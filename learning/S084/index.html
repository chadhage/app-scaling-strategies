S084 — Retry the same commands, not their effects

Inspect fixed provisioning, routing and cleanup deliveries. Recognize a duplicate resource or an unintended second swap; a command receipt is not a safety verdict.

One fixed, bounded trace

Preconditions: retained-v1 is the old synthetic resource. Three originals record candidate-v2, swap routing to it, then remove retained-v1. Three retries reuse those exact operation keys and payloads. Resource names, command labels, actor stamps and swaps are only fixture data.

Actions: inspect originals → retry the same keys → verify → predict and retain. Compare remembered results with blind replay. An unavailable cleanup receipt must remain unknown.

There is no shell, file, resource or management operation behind these controls. Blind replay is a deliberately broken synthetic counterexample, not an Azure command behavior.

Limits and expected assertions

      
Remembered results plus complete receipts: PASS, one candidate, one swap, one removal, six known delivery outcomes. Blind replay: FAIL, one duplicate resource, an unintended second swap to a missing target, and a cleanup retry error. Missing cleanup evidence: UNKNOWN unless a known failure already exists; unknown deliveries are never discarded.

      
Resource and route gates describe the last observed checkpoint. With an unavailable cleanup receipt, final state is unverified even if that checkpoint looked safe. These six command deliveries are not user journeys, a migration success rate or evidence of five-nines reliability.
