S026 — Slow image pull or startup

A-S026 · D-S026 · SC-S026 · one frozen Kano S unit

Keep the old GA deployment serving while an immutable candidate image is pulled and initialized. A downloaded image alone is not readiness.

Model preconditions and limits

GA is assumed healthy with sufficient overlap capacity. The candidate is assumed compatible. Each tick supplies exactly three successful, in-budget synthetic requests. These assumptions are not measured Azure behavior or business-journey evidence.

Pull and initialization are sequential. Both require observed success before handoff. At the selected tick the model attempts one guarded handoff; before then GA serves. Choosing an answer cannot bypass that guard. No real image is downloaded or started.

The fixed candidate reference uses a synthetic SHA256 digest, not a mutable tag. Ticks are deterministic steps, not elapsed seconds. No timers, services, accounts or network are needed.

Conduct the rehearsal

Choose delays, inject a condition, select an observation tick, then predict whether handoff is allowed. Check the trace and compare a waiting run with a ready run.
