S057 · Old HTML, immutable assets

Deploying new HTML does not rewrite an existing page's asset references. Keep the old required assets available while that HTML can still be used.

Local deterministic model only: “cache”, “deploy”, “retire”, 200 and 404 below are synthetic state and observations. No real HTML cache, CDN, HTTP request, native deployment or asset deletion occurs.

Conduct the experiment

  1. Cache HTML v1, then publish HTML v2 with distinct immutable script and stylesheet identifiers.
  2. Optionally retire the selected old assets before loading the cached page.
  3. Load cached HTML v1 after deployment. Inspect each required asset, not just the new page.
  4. Load current HTML v2 for comparison, then check your prediction.
  5. Retain the attempt and compare with old assets kept. Prior failures remain visible.

Exactly two page loads and four required assets per attempt. Pending or withheld observations remain unknown. Six attempts maximum; history lasts until explicit reset or page reload. No retries, latency claim, real user or reliability certification.
