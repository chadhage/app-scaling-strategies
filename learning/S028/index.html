S028 — Warm-up timeout

Objective: Expire preparation, leave the production routing command intact, and distinguish a safe abort from completed user migration.

Source S028: “Warm-up timeout: Abort explicitly and leave existing production routing intact.” D-S028 requires a configurable timeout, Abort preparation, a visible error, and a safe-abort result. A-S028 · frozen S · SC-S028 · SOURCE.

Conduct the rehearsal

  1. Start the defaults. Advance three synthetic seconds: the deadline aborts warm-up before the candidate is ready.
  2. Inspect the timeout error, unchanged 100/0 routing, production receipts and zero migrations. A correct safe abort is not a successful migration.
  3. Archive/reset. Try Abort preparation early, or readiness at 2 seconds with a 4-second timeout. Early readiness is still preparation only.
  4. Choose a drifted/missing routing witness or failed/unknown receipt. The verifier must report failure/unknown instead of assuming continuity.

Precondition: a synthetic existing production version serves all traffic. One request receipt and routing observation are generated at start and each action. Time advances only on a button press; no timers, traffic switches or management calls run. Readiness must arrive strictly before the deadline.
