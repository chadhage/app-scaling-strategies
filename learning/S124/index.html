Source, hosting constraints and limits

A-S124 / D-S124 / SC-S124 · one original Kano S unit. D-S124 requires real capacity, cost, routing, drain and user-outcome evidence; this portable lesson does not complete that native acceptance.

Supporting App Service plans are required for native slots. Slots share plan instances; per-app placement adds no plan capacity. Native swaps can recycle former-production workers and abandon old work. Retaining old slot content does not prevent that recycling. Slot cookies can pin clients despite traffic weights.

Native auto-swap is unsupported for Linux code and Web App for Containers. This lesson selects no actual OS, SKU, region or hosting target and offers no native auto-swap, cloud or management interface.

External routing separates new-admission, drain, rollback-retention and retirement decisions; it cannot eliminate host restarts or qualify wider failure domains. B-S124 native proof and D-S124 remain incomplete. No production Node.js 24, native Azure or five-nines result is claimed.

This fixed comparison uses a native shared-slot swap versus an externally routed separate-plan path. External routing is not exclusive to separate plans: independently routable shared-plan slots can also use controlled admission and draining, while still sharing compute. Plan placement and routing mechanism are separate axes.
