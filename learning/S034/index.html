S034 — Authentication-key continuity

Keep existing cookie/token validation compatible while v1 and v2 overlap during planned rotation. An expected authentication failure is still a failed migration, not a successful user transition.

What this rehearsal measures

  1. v1 issues public label fixture-old; v2 issues fixture-next. These are labels, not cryptographic keys or real credentials.
  2. Each synthetic profile attempts two valid-credential journeys: old from v1 to v2, then next from v2 to v1. Overlap lets both versions validate both labels.
  3. Compare overlap with incompatible policies: v1 accepts only old, v2 accepts only next. Both must still reject tampered fixtures. Missing replies remain unknown.

The denominator is all attempted cross-version journeys, including failures and unknowns. Baseline and tamper guard probes are separate, not successful migrations.

Operator controls

Use one digit from 1 to 8; maximum 16 measured journeys per run. A missing reply masks only the final v2 → v1 observation, never every known rejection.
