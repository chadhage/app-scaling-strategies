A-S112: FICTIONAL ZONE-WORKLOAD ISOLATION

Training rehearsal - synthetic data - not a live Azure result

Open learning\S112\index.html directly in a browser.
No setup, subscription, packages, server or framework is required by the lesson.

EXACT SOURCE AND BOUNDARY
S112: Availability-zone loss: Test supported compute/data redundancy and
sufficient surviving-zone capacity.
D-S112: Surviving workload/data capacity is measured; the injected zone-workload
fault is labeled as an outage proxy, not an actual Azure-zone outage.
A-S112: Isolate a zone's fixture workloads; do not label it an actual Azure-zone
outage. One frozen S unit; packet SC-S112; owner worker-A-S112.

This exercise calculates fixed fictional teaching data only. Its zones,
placement, failure, topology, compute/data capacity, recovery and journeys do
not represent an observed live system. It does NOT isolate a process, pod, VM,
network, resource, leased workload or Azure zone. "Outage-proxy rehearsal" names
the teaching scenario, not an injected real fault. Native B-S112 and source
parent D-S112 remain incomplete.

WORKED EXERCISE
Load "Redundant compute and observed data", select zone-a, check fictional
placement, confirm data-only isolation, isolate records, then measure.
Only the selected zone's fictional application/data record becomes unavailable.
The other two fictional zones have four compute units and four observed data
units. All four fixed profile reads succeed at 8/9/10/11 teaching ticks against
a 12-tick budget. Those numbers are not wall-clock latency or platform capacity.

Repeat with "Insufficient surviving compute": zone-a leaves two compute units.
Two journeys succeed and two are interrupted. The lesson expectation matches,
but the verifier remains FAIL, not success.

Repeat with "Data exists only in fictional zone-a": enough compute survives but
zero data units do; all four attempts are interrupted. Selecting zone-b or
zone-c instead does not lose that fictional data replica.

Repeat with "Surviving data observations are unknown": data capacity is UNKNOWN
(null), not zero or configured capacity. All four outcomes remain unknown and
the verifier is UNVERIFIED. Restoring the records does not invent observations.

Restore records and check recovery separately. A new recovery measurement never
rewrites the original failed/unknown attempts. Reset archives both measurements
and the ordered actions and clears fictional isolation. Reset while idle is
idempotent. Six archived runs are a hard bound; no report is silently removed.
History is memory-only and does not survive page reload.

CONTROLS AND GUARDS
Only four immutable fixture IDs, three fictional zone IDs and the seven named
operator actions are allowed. Inputs are exact typed own data fields, without
coercion, unknown fields, accessors or arbitrary state objects. Commands follow
load -> placement -> confirmed isolation -> measure -> restore -> recovery.
Reset is available throughout. Only data records change. State is deeply frozen.
Keyboard controls, focused actionable alerts, explicit disabled-step reasons,
separate verifier/journey impact/cleanup and retained history are included.
Reset uses an outside-form reset-lesson button, not a form.reset-shadowing name.
Only local external scripts/styles are permitted; connections, inline scripts,
frames, objects, workers and form submissions are forbidden by CSP.
