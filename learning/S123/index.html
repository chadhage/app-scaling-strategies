S123 · Prepare an immutable custom container

Prepare an immutable container; detect startup assumptions and unsupported automatic swap.

Every container, image, digest, registry, startup, readiness, platform, promotion and journey field below is fixed fictional teaching DATA ONLY. No image is built or pulled; no registry, resource, configuration, deployment, native swap or IaC operation occurs.

Hosting constraints and exercise

  1. Select a fixed fixture and a controlled manual or pipeline path. Prepare the digest-pinned candidate.
  2. Inspect startup and readiness: a pull, correct listening port, completed initialization, dependencies, explicit acceptable warm-up status and meaningful readiness must agree.
  3. Check overlap before promotion. Slots share plan instances; extra slots add no compute capacity.
  4. Rehearse a controlled promotion, then measure complete candidate journeys, not just a green probe.

Native auto-swap is unsupported for Linux web apps and Web App for Containers. The rejection control demonstrates that limitation, not a working automatic swap.

Native App Service swaps can recycle former-production workers and abandon active work. Here recycling and client outcomes are modeled DATA, not observations of Azure. No startup command or configuration is applied.
