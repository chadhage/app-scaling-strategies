SHAPES / EVIDENCE
The exact trace fields are schemaVersion=1, dataKind, fixtureId, resource,
request, windows[7], injection, detection, recovery, and journeys[3].
resource has id and version. request has id, fault=TRACE, phase, atMs,
clockId, epoch. Each window has phase, startMs, endMs, clockId, epoch,
resourceId, version, observationId. Each observation has requestId, atMs,
clockId, epoch, resourceId, version, observationId; injection also has
fault=TRACE, occurred, phase; detection has detected; recovery has recovered.
Journeys also have id, window=before/during/after, and result
continuous/interrupted/unknown. Null means unobserved, not a default value.
Only booleans or null are accepted for occurred/detected/recovered; clocks are
safe integers in 0..10000 or explicitly null, never strings/floats/truthy values.
IDs are bounded typed tokens. Extra/accessor fields, sparse arrays, duplicate
observation/journey IDs, wrong order, and overlapping aligned windows are rejected.

Fixed observed windows (fictional ms, inclusive start / exclusive end):
provisioning [0,1000), warming [1000,2000), promotion [2000,3000),
serving [3000,4000), draining [4000,5000), rollback [5000,6000),
cleanup [6000,7000). An injection at end belongs outside that phase.
Coverage requires observed occurrence, injection observation/time, actual phase
observation, observed window, matching request/resource/version, and identical
known clock/epoch. A requested time never substitutes for an actual timestamp.
Missing clocks/windows/scopes, mismatched labels, and unobserved native timing
stay UNCOVERED. Detection, recovery, and impact are classified separately.
Known interruption dominates later uncertainty. Positive fixed samples must
join the actual fault/recovery clocks and have observed temporal placement;
their before/during/after labels alone do not prove placement or continuity.
NO_OBSERVED_INTERRUPTION is sample-only, not success throughout the window.
