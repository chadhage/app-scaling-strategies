Remove worker affinity only after state is safe

Objective: distinguish a successful pinned baseline from verified externalization, then compare worker affinity on and off without silently resetting required user state.

A worked, bounded comparison

Two synthetic clients each have a cart, workflow step and revision, initially present only on worker-a. Affinity on sends all four probe requests there. Affinity off uses the fixed order client-1/a, client-1/b, client-2/a, client-2/b.

  1. Probe current routing: 4/4 pinned replies match, but local state is still unsafe to unpin.
  2. Remove worker affinity first: explicit safe abort; affinity remains on.
  3. Preview unsafe off + local order: 2/4 state checks fail despite four HTTP 200s. This counterexample is not applied.
  4. Externalize and verify state with complete receipts, then probe while still pinned. Remove affinity and probe again: 4/4 matching states across both workers.
  5. Try mismatch or missing observations. Failure and unknown are distinct; neither is success. Open older history entries to inspect their retained traces.

    Preconditions, assertions and limits

    Source: README.md S033, “Worker-affinity removal”; backlog D-S033; portable card A-S033. A complete migration requires matching receipts for both clients and all three state fields. Missing receipts cannot establish verification, and mismatches are explicit failures. Unsupported removal is blocked before exposure; the separate unsafe preview shows why.

    This finite model assumes compatible readers and an atomic shared-state migration. One in-memory map is not durable storage. There are no concurrent writes, authentication, real cookies, actual routing changes, Azure resources or management calls. This is worker affinity, not slot-routing-cookie migration.

    All values are synthetic and fixed. Observational faults do not modify stored state. History is retained only in this page, for up to 16 steps; reset or reload clears it. No credentials, packages, network requests or browser persistence are needed.
