Declare before moving

What must survive?

Each client has a different profile ID, display name, theme, cart, draft and nonzero revision. Every field and schema 1 must match. HTTP status, client identity, version and instance must also match the requested read.

The declaration is fixed. Reading an empty/default profile does not redefine success. One passing read cannot erase an earlier interruption or unknown result.

Preconditions: both synthetic application versions understand schema 1; each client keeps its invented session key. Identity/authentication, serialization upgrades and actual routing are not under test.

    What this demonstrates — and what it does not
    
      
    A shared lookup by the same client key preserves this declared synthetic state across all four destinations. Local memory only has a profile at its seeded instance. Empty, default, stale, misbound and unknown replies cannot pass the state contract just because HTTP says 200.
    
      
    This read-only model has no network, credentials, Azure management calls, storage persistence, authentication, concurrency, eviction, writes or real failover. It does not prove a store's durability, a live deployment, B-S031 native continuity or full D-S031 acceptance.
