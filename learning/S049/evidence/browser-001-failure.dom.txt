    <h1>S049: Ambiguous POST completion</h1>
    <p>Commit one synthetic order, lose its response, then choose a controlled retry.
      A lost reply is not a rollback. A retry is not automatically safe.</p>
    <p><strong>Objective:</strong> distinguish one business effect with the correct client result
      from duplicate effects, explicit rejection, and an unresolved client.</p>
    <p>Source: <a href="../../README.md#e-in-flight-requests-and-long-lived-work">README S049</a>;
      parent D-S049; card A-S049; frozen S; packet SC-S049.
      <a href="README.md">Instructions and evidence</a>.</p>
  </header>

    <section aria-labelledby="preconditions">
      <h2 id="preconditions">One fixed operation, bounded synthetic time</h2>
      <p>The original request is POST synth-order for <strong>10 units</strong> with
        <code>synth-key-A</code>. All keys, effects and amounts are synthetic.
        No account, server, credentials, subscription or real request is used.</p>
      <p>The atomic option assumes one shared, durable, atomic key + payload + remembered-result ledger.
        This portable model does not prove a real transaction or distributed protocol.
        A new key names a new operation; changing the payload with the old key is a conflict.</p>
    </section>
