S053 — Software releases are not API contracts

A-S053 · D-S053 · SC-S053 · one frozen S learning unit

Introduce a breaking API using versioned endpoints or a transitional adapter. A forced endpoint switch is not safe just because it responds with HTTP 200.

Fixed synthetic envelope

Three profile consumers initially require v1: { displayName: "Ada Example" }. Blue software 1.8.0 serves v1. Green software 2.0.0 uses v2: { name: { given: "Ada", family: "Example" } }. Both shapes refer to the same fixed synthetic profile.

An explicit client upgrade changes the declared consumer contract before an attempt. A software deployment does not. Green can preserve v1 through a transitional adapter at a stable route or a retained v1 endpoint; it does not pretend v1 consumers understand v2.

Each independent cutover attempt starts from this fixture and contains exactly three journeys. Inspect the response shape and observed software identity. API paths and HTTP statuses below are model data, not requests. No account, server or credentials are needed.

Operator controls

Try a mixed population with an adapter, then force v2 without upgrading every consumer. Failures stay in history. At most six attempts; no randomness, timers, storage or network.
